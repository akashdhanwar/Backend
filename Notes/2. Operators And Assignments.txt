- Increment and Decrement Operators
Includes pre and post operators

-------------------------------------------------------------------------
|   Expression   |   Initial(x)     |   Value of y      |   Final(x)    |
-------------------------------------------------------------------------
|   y = ++x;     |       10         |   11              |   11          |
|   y = x++;     |       10         |   10              |   11          |
|   y = --x;     |       10         |   9               |   9           |
|   y = x--;     |       10         |   10              |   9           |
-------------------------------------------------------------------------

Only for variables and not for constants. 
    Example -   int y = ++(++x);    CE: required variable, found value
For final variables, no increment/decrement
For every primitives except boolean
    
Difference between b=b+1 and b++
    b = b + 1;  -   max(int, type of a, type of b)
                    byte b = 10;
                    b = b + 1;          
                    sop(b);
                    CE: Possible loss of precision
                    b = (byte)(b+1);
    b++;        -   b = byte
                    b = (type of b)(b+1)
                    Internal Type Casting

- Arithmetic Operators
Result type - max(int, type of a, type of b)

Infinity
    In integral arithmetic(byte, short, int, long) there is no way to represent Infinity. Hence ArithmeticException
    Example -   sop(10/0);      RE: ArithmeticException
    
    But in floating point arithmetic(float and double) there is a way to represent Infinity.
    For this, Float and Double classes contains the following two constants 
    POSITIVE_INFINITY
    NEGATIVE_INFINITY
    Hence even though result is Infinity, no ArithmeticException in floating point arithmetic
    Example -   sop(10.0/0);        Infinity
                sop(-10.0/0);       -Infinity
                sop(0/0);           RE: Division by zero
                sop(0.0/0);         NaN 

NaN(Not a Number)
    In integral arithmetic, there is no way to define undefined hence RE
    But there is a way in floating point arithmetic
    For this, Float and Double classes contains NaN constant
    Example -   sop(-0.0/0);

    sop(10 < Float.NaN);                false
    sop(10 <= Float.NaN);               false
    sop(10 > Float.NaN);                false
    sop(10 >= Float.NaN);               false
    sop(10 == Float.NaN);               false
    sop(Float.NaN == Float.NaN);        false
    sop(10 != Float.NaN);               true
    sop(Float.NaN != Float.NaN);        true
    
Summary 
    Arithmetic Operators gives RE and not CE
    Possible in integral arithmetic but not in floating point
    Only operators that cause ArithmeticException are / and %

- Bitwise Operator(&, |, ^)
& = AND         true If both true
| = OR          true If atleat one true
^ = X-OR        true If both different
We can also apply these for integral types

Examples    -   sop(4 & 5);                     4(100 & 101 = 100 = 4)
                sop(4 | 5);                     5(100 | 101 = 101 = 5)
                sop(4 ^ 5);                     1(100 ^ 101 = 001 = 1)
                sop(true & false);              false

- Bitwise Compliment Operator(~)
Only for integral and not for boolean
MSD acts as a sign bit
+ve numbers represent directly
-ve numbers in 2'nd complement form
Examples    -   sop(~true);                     CE
                sop(~4);                        -5(4 = 0 0000....0100)
                                                  (~4 = 1 1111....1011)
                                                  (1's complement + 1 = 1 0000....0101)
                                                  (1 0000....0101 = -5)

- Boolean Complement Operator(!)
Only for boolean types
Examples    -   sop(!true);                     false
                sop(!4);                        CE

Summary 
    & | ^   -   for both integral and boolean
    ~       -   for integral
    !       -   for boolean

- Short Circuit Operators
These are same as bitwise operators, except the following differences

------------------------------------------------------------------------------------------
|                   &, |                      |                &&, ||                    |  
------------------------------------------------------------------------------------------
|   Both arguments always evaluated           |  Second argument evaluation is optional  |               
|   Relatively low performance                |  High performance                        |
|   Applicable for both boolean and integral  |  Applicable only for boolean             |
------------------------------------------------------------------------------------------

x && y    -    y will be evaluated only if x is true
x || y    -    y will be evaluated only if x is false

Examples -
    int x = 10;                         |       int x = 10;
    int y = 15;                         |       if(++x < 10 && (x/0 > 10)){
    if(++x < 10 & ++y > 15){            |            sop("Hello");
        x++;                            |       } else {
    } else{                             |            sop("Hi");
        y++;                            |       }
    }                                   |
    sop(x + " " + y);                   |

- Typecast Operators(Implicit, Explicit)

- Implicit Type Casting
Compiler converts chat to int by implicit type casting
Small to big conversion -> Widening

Example - int x = 'a';
          sop(x);

- Explicit Type Casting
If we assign floating point values to integral types by explicit type casting, the digits after decimal points will be lost.

Example - int x = 130;
          byte b = x;                CE: PLP
          byte b = (byte) x;         Right, but big to small -> Narrowing, Loss of Precision
          sop(b);                    -126        130 ->    0000....0010000010
                                                           10000010 -> MSD Lost in sign
                                                           2's complement of rest -> 126

          int x = 150;
          short s = (short) x;       150
          sop(x);
          byte b = (byte) x;         10010110 -> -1101001 + 1 -> 1101010 -> -106

          double d = 130.456;
          int x = (int) d;           130
          sop(x);
          byte b = (byte) d;         
          sop(b);                    10000010 -> -1111101 + 1 -> -126

- Evaluation order of Java Operands
In Java, we have only operator precedence but not operand precedence.
Before applying any operator, all operands will be evaluated from left to right.

Example - class Test {
              psvm(String[] args){
                sop(m1(1) + m1(2) * m1(3) / m1(4) + m1(5) * m1(6));                1 + 6/4 + 30 -> 1+1+30 -> 32
              }

              public static int m1(int i){
                sop(i);                                                            1 2 3 4 5 6
                return i;
              }
          }

- new vs newInstance()
We can use new operator to create an object if we know classname at the beginning
Example - Test t = new Test();
          Student s = new Student();

newInstance() is a method in class Class.
We can use newInstance() to create object if we dont know classname at the beginning & it is available dynamically at runtime.
Example - class Test{
            psvm(String[] args) throws Exception;
            { 
                Object o = Class.forName(args[0]).newInstance();
                sop("Created for " + o.getClass().getName());                    java Test Sudent -> Created for Student
            }
          }

Note - In case of new operator based on our requirement we can invoke any constructor.
       Example - Test t1 = new Test(10);
                 Test t2 = new Test();
                 Test t3 = new Test("Akash");
       But newInstance() internally calls no-args constructor. 
       Hence we use newInstance(), compulsary corresponding class should contain no-args constructor else RE: InstantiationException
       Used in Servlets

Note - Test t = new Test();                                                                 RE: NoClassDefFoundError:Test
       Object o = Class.forName.(args[0]).newInstance();                                    RE: ClassNotFoundException:Test
       While using new operator, if at runtime corresponding .class file not available then RE: NoClassDefFoundErrorr:Test 
       for newInstance()                                                                    RE: ClassNotFoundException:Test
